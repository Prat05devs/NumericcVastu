# Maintaining offers and preparing Razorpay

Edit **only** [`src/data/offers.ts`](../src/data/offers.ts) to change a course or consultation name, description, included features, price, availability, or scheduled promotion. The homepage previews, catalogue, detail routes, booking selection, XML sitemap, and Course structured data read that catalogue. The file is the commercial source of truth.

Each offer has a permanent `id` (for future orders), a public `slug`, `kind`, display copy, `pricePaise`, `priceVerified`, `checkoutEnabled`, and `active`. Prices are integer **paise**, so ₹29,999 is `2999900`. The displayed INR amount comes from `formatPrice`; never type a second amount into page copy. `featuredOfferId` selects the course used by the homepage hero and site-wide announcement; change that ID here when the featured course changes. The current amounts were copied from the existing site for migration review. All are marked `priceVerified: false` and `checkoutEnabled: false`.

To update an existing offer: change its record and, if the price was approved, set `priceVerified: true`. Keep `checkoutEnabled: false` until the payment integration and commercial policies are complete. To add an offer: add a new unique `id` and `slug`, the required fields, and a valid positive paise amount. To retire an offer: set `active: false`. Decide whether its previous URL should redirect or keep a useful archived page before publishing.

**Rupees and dollars.** Every offer also has `priceUsdCents`, its fixed US dollar price ($690 is `69000`). Visitors in India see and pay rupees; everyone else sees and pays dollars. The October 2026 rule for setting dollar prices: double the rupee price, convert at ₹88 = $1 and round up to the next $10. The dollar amount does not follow the rupee amount automatically, so update both when a price changes. Pages show prices with `<Price offer={…}/>` (both currencies are rendered and CSS shows the visitor's), and checkout charges the currency the server works out from the visitor's country; see [`src/lib/currency.js`](../src/lib/currency.js). That needs the host's country header (Vercel's `x-vercel-ip-country` or Cloudflare's `cf-ipcountry`); without one, the visitor's device time zone decides. Indian visitors pay through Razorpay; visitors abroad pay through PayPal, and also by card through Razorpay once `RAZORPAY_INTERNATIONAL=on` (see `.env.example`).

To create a limited offer, add an entry to `promotions` with a unique `id`, visible label, `offerIds`, integer `discountPaise` (and optionally `discountUsdCents`; without it the dollar price gets the same percentage off), ISO 8601 `startsAt` and `endsAt`, and `enabled: true`. The price helper calculates the current amount using those dates. The site-wide announcement highlights the latest active course promotion; otherwise it presents the featured course without implying a discount or deadline. Course cards show only promotions active for that course. The catalogue validator rejects duplicate IDs/routes, bad amounts, unverified checkout, invalid intervals, and discounts greater than the base amount. Do not use a client clock or client amount for a payment order.

The future Razorpay order endpoint should take **only `offerId`** from the browser and call [`resolveCheckoutOffer`](../src/lib/checkout.ts) on the server. That helper checks availability, verified price, and checkout status; it returns amount in paise, INR currency, and catalogue version. The server must create and persist an order snapshot containing offer ID, version, final amount, promo ID where applicable, taxes and policy version. Create the Razorpay order with that amount. Verify Razorpay payment signatures and webhook events server-side, match order and paid amounts, handle repeat webhooks idempotently, and confirm a booking only after the verified payment and appointment reservation succeed. Never accept a browser-supplied fee, discount or “payment successful” flag.

No Razorpay keys, orders, checkout button, or payment callbacks are active yet. The enquiry page clearly says it does not reserve a time or take payment. Confirm taxes, cancellation and refund rules, availability, payment account, and final course/service details before enabling checkout.

A catalogue edit is a code change and requires deployment. Once deployed, offer pages revalidate every 60 seconds; the Razorpay endpoint must always resolve the current amount on the server at order creation. If the visitor saw an earlier amount, show the server's current price for confirmation before payment. For no-deploy editing, the same catalogue contract can later move to an authenticated CMS or database; do not maintain two independent price stores.

Course detail pages (`/courses/[slug]`) also read long-form copy from [`src/data/courseDetails.ts`](../src/data/courseDetails.ts), keyed by offer `id`: learning outcomes, requirements, description, module outline, certification wording, FAQs and course facts. That file never holds a price. A fact left `null` (format, duration, language, next batch, access) is not shown. Set `syllabusConfirmed: true` only after replacing the module outline with Adarshh's approved lesson-by-lesson syllabus; until then the page says the outline is provisional.
